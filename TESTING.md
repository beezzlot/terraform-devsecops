| Тест | Ресурс | Результат | Интерпретация результата и вывод для проекта |

| `CKV_YC_2` — отсутствие публичного IP | `web` VM | PASS | Для сетевого интерфейса задано `nat = false`, поэтому публичный IP не назначается |

| `CKV_YC_11` — security group назначена | `api` VM | FAIL | В блоке `network_interface` отсутствует `security_group_ids`. Для production-инфраструктуры рекомендуется создать security group и назначить её VM |
| `CKV_YC_11` — security group назначена | `web` VM | FAIL | В блоке `network_interface` отсутствует `security_group_ids`. Проблему желательно исправить, чтобы явно ограничить сетевой доступ |

Обнаруженные проблемы связаны с отсутствием security group у виртуальных машин `web` и `api`. В текущей учебной конфигурации VM не имеют публичных IP, поэтому риск прямого доступа из интернета снижен. Однако отсутствие security group не позволяет явно описать разрешённые входящие и исходящие соединения.

Для production-окружения проблему необходимо исправить: создать security group с минимально необходимыми правилами и передать её идентификатор в `security_group_ids`. Для текущей учебной работы проблема зафиксирована в отчёте как результат статического анализа и не исправлялась, чтобы показать работу Checkov.

### Детали результата

Terraform plan содержит четыре ресурса для создания:

```text
Plan: 4 to add, 0 to change, 0 to destroy
```

В состав плана входят:

- виртуальная машина `api`;
- виртуальная машина `web`;
- дополнительный диск `backup`;
- дополнительный диск `logs`.

Для сетевых интерфейсов виртуальных машин указано:

```text
nat = false
```

Следовательно, виртуальные машины не получают публичные IP через NAT.

Дополнительные диски имеют следующие параметры:

```text
device_name = "backup"
device_name = "logs"
size        = 20
type        = "network-hdd"
```

Параметры окружения `dev` соответствуют ожидаемым:

```text
zone        = "ru-central1-a"
platform_id = "standard-v3"
```
